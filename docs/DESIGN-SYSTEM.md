# DESIGN SYSTEM — 이 앱의 색·글자·간격은 여기서만 정한다

> 값은 전부 `src/renderer/src/tokens.css`에 있다. 이 문서는 **왜 그 값인가**를 적는다.
> 토큰 파일은 "무엇을 어디에 쓰는가"만 적는다. 같은 설명을 두 군데 두면 반드시 어긋난다.

## 0. 이 앱은 무엇인가 (체계가 여기서 나온다)

공공 SI 현장의 **모델링 작업 도구**다. 사용자는 요구사항정의서를 넣고, 트리와 폼에서
유스케이스를 몇 시간씩 다듬고, EA에 임포트할 XMI를 내보낸다. 화면 옆에는 거의 항상
Enterprise Architect 창이 같이 떠 있다.

그래서 세 가지가 정해진다.

1. **마케팅 페이지가 아니다.** 큰 여백도, 페이지 뜰 때 올라오는 효과도, 히어로 섹션도 없다.
   이 앱의 주역은 트리와 폼이다. 밀도는 VS Code · EA Project Browser 쪽이다.
2. **오래 본다.** 하루 여섯 시간 보는 화면에서 채도 높은 색은 피로가 된다.
   강조색은 한 곳에만 쓰고, 나머지는 거의 무채색이다.
3. **윈도우 폐쇄망 설치본이다.** 내려받는 글꼴이 없다. 운영체제에 이미 있는 것만 쓴다.

## 1. 색 — "종이와 먹"

### 왜 이 방향인가

바꾸기 전은 `#f4f6f9`(차가운 청회색) 바탕에 `#2563eb`(Tailwind blue-600) 강조였다.
문제는 두 가지였다.

- `#2563eb`는 **모든 업무 SaaS가 쓰는 그 파랑**이다. 공공 현장 도구는 특히 전부 파랑이다.
  선택이 아니라 기본값이었다.
- 차가운 청회색 바탕은 윈도우 창 테두리와 같은 색조라, 앱이 **창틀의 연장**처럼 보이고
  정작 내용이 사는 흰 면이 떠오르지 않았다.

그래서 바탕을 **아주 옅게 따뜻한 중성(종이)** 으로 옮겼다. 흰 패널과 흰 캔버스가
그 위에서 "놓인 종이"로 읽힌다 — 이 앱이 하는 일이 실제로 도면을 그리는 일이다.
글자는 차가운 검정 대신 **따뜻한 먹색**이다. 따뜻한 종이 위의 찬 검정은 탁해 보인다.

### 왜 남색(`#2e3a8c`)인가 — 그리고 왜 청록이 아닌가

강조색은 **의미색 3개와 겹치면 안 된다.** 녹색은 성공, 호박색은 경고, 빨강은 오류가
이미 가져갔다. 캔버스의 강조까지 호박색이어서 "선택"과 "경고"가 같은 색이었다.

남은 자리는 파랑–보라 띠다. 그 안에서:

- 청록(`#0e6e60`)을 먼저 골랐다가 **버렸다.** 11px 글자 크기에서 성공색(녹색)과 구별이
  안 된다. 검증 결과를 숫자로 읽는 화면에서 강조와 성공을 혼동하는 건 치명적이다.
- 밝은 SaaS 파랑은 기본값이라 뺐다. 보라는 스타트업 도구의 색이다.
- **남색 먹**은 종이 위 잉크로 읽히고, 의미색 셋 어디와도 멀고, 흰 글자를 올렸을 때
  대비 10.0 으로 버튼에 쓸 수 있다. 공공 도구의 밝은 파랑과도 분명히 다르다.

### 값과 근거 — 다크

다크도 **따뜻한 중성(흑연)** 이다. 파란 검정은 쓰지 않는다 — 라이트가 따뜻한 종이인데
다크만 차가우면 같은 앱으로 안 보인다.

| 토큰 | 값 | 왜 |
|---|---|---|
| `--bg` / `--bg-1` / `--bg-2` | `#161614` `#1e1e1b` `#282824` | 다크에서는 면이 **위로 올라갈수록 밝아진다**. 라이트와 반대 방향, 같은 세 단계 |
| `--fg` / `--fg-dim` / `--fg-mute` | `#edebe6` `#afaaa2` `#969189` | `--fg-mute`는 `--bg-2` 위 4.7. 라이트와 같은 이유로 정해진 값이다 |
| `--accent` | `#a3aef7` | **다크에서는 강조색이 둘로 갈린다.** 이건 글자·선·포커스 링용 |
| `--accent-fill` | `#3d4aae` | 주 버튼 배경. 밝은 남색 위에 흰 글자를 올리면 대비가 2.1로 떨어져 읽히지 않는다 |
| `--ok/warn/err` | `#6fd69b` `#e8b562` `#f28b82` | 어두운 바닥 위 7.6~10.2 |

### 캔버스 — 토큰이 아닌 것이 섞여 있다

유스케이스 노드 **안쪽 색은 토큰이 아니다.** `src/shared/constants.ts`의 EA 요소 배경
7색이 그대로 칠해지고, 그 값은 XMI에 저장되는 산출물이라 테마에 따라 바뀌면 안 된다.

그래서 **노드 위에 올라가는 글자색은 7색 전부에서 읽혀야 한다.**

- `--node-text` `#1c1a17` — 7색 중 최저 대비 9.6
- `--node-code` `#4a453f` — 7색 중 최저 5.3. 11px 글자다. `--fg-mute`를 그대로 쓰면
  파랑·보라·주황 노드 위에서 3.1까지 떨어진다. **이 토큰만 유독 진한 이유가 이것이다**
- 노드 안 글자색은 **다크에서도 같은 값**이다. 노드 안쪽이 밝은 파스텔로 고정이라,
  다크라고 글자를 밝히면 노드 위에서 사라진다. 다크에서 바뀌는 건 캔버스 바닥과
  바닥에 직접 그려지는 선(액터·연결선·테두리)뿐이다
- `--link`는 글자가 아니라 선이지만 **뜻을 가진 선**이라 3:1을 지킨다 (라이트 3.3 / 다크 3.5)

## 2. 글자

### 서체 2개

| 토큰 | 값 | 왜 |
|---|---|---|
| `--font-ui` | `'Segoe UI', 'Malgun Gothic', system-ui, sans-serif` | 폐쇄망 설치본이라 내려받는 글꼴이 없다. 윈도우에 반드시 있고, 한글이 이 플랫폼에 맞게 힌팅된 조합이다 (Segoe UI에 한글이 없어 한글만 Malgun Gothic으로 떨어진다) |
| `--font-mono` | `'Cascadia Mono', Consolas, ui-monospace, monospace` | `UC-SFR-001-PAD-02-01` 같은 ID는 **자리를 세어 읽는다.** 고정폭이 아니면 `-01`과 `-10`이 다른 길이로 보인다. Consolas는 모든 윈도우에 있다 |

### 크기 5단계 — 단계마다 역할이 **하나**다

고치기 전 styles.css에는 9·10·11·11.5·12·13·14·15·16·30px가 섞여 있었다.
단계가 많으면 그건 단계가 아니라 그냥 제각각이다.

| 토큰 | 값 | 역할 | 왜 |
|---|---|---|---|
| `--fz-xs` | 11px | ID·코드·칩·트리 오른쪽 숫자 | 고정폭 ID가 좁은 칸에 들어가야 한다. 11px이 한글이 뭉개지지 않는 하한 |
| `--fz-sm` | 12px | 라벨·보조 설명·툴바 버튼 | |
| `--fz-md` | 13px | **본문 기본값.** 입력칸·트리 줄·폼 | VS Code·EA의 조밀한 밀도가 13px다. 14px로 올리면 트리에 보이는 줄 수가 줄어든다 |
| `--fz-lg` | 15px | 패널·화면 제목 | 본문과 2px 차이 + 굵기 600으로 제목이 된다. 더 키우면 업무 도구가 아니라 웹페이지가 된다 |
| `--fz-xl` | 20px | 빈 화면의 안내 한 줄. **한 화면에 한 번만** | 빈 상태는 "여기서 뭘 하는지"를 말해야 하고, 그게 그 화면의 유일한 주역이다 |

### 굵기 2개

`--fw-normal: 400` / `--fw-medium: 600`.
Segoe UI의 500은 윈도우에서 400과 거의 구별되지 않아 단계가 생기지 않는다. 600이
또렷한 두 번째 굵기다. **700은 쓰지 않는다** — 13px에서 한글 획이 뭉친다.

### 행간 3개

`--lh-tight: 1.2`(제목) / `--lh-body: 1.6`(본문) / `--lh-ui: 1`(버튼·칩처럼 높이를 패딩으로 잡는 것).
1.6인 이유: 한글은 글자가 네모지고 빽빽해서 1.2 근처면 줄끼리 붙어 덩어리로 안 보인다.
1.6은 줄 사이가 글자 크기의 절반을 넘어 **줄이 하나의 단위로 읽히는** 최소선이다.

본문 블록은 `--measure: 72ch`로 줄 길이를 끊는다. 80자가 넘으면 다음 줄 첫 글자를 놓친다.

### 글자로 하지 않는 것

- 제목 안의 한 단어만 색·굵기를 바꾸지 않는다
- **대문자 라벨(`DETAILS`), 자간 벌린 라벨을 쓰지 않는다.** 한글에는 대문자가 없어
  영문 라벨만 그렇게 되면 화면에 두 개의 글자 체계가 생긴다
- 내용 위에 덧붙이는 장식 라벨을 쓰지 않는다

## 3. 간격 — 4px 배수만

`--s1` 4 / `--s2` 8 / `--s3` 12 / `--s4` 16 / `--s5` 24 / `--s6` 40

**쓰는 법이 값보다 중요하다:** 같은 묶음에는 같은 값을, 다른 묶음 사이에는 반드시
**한 단계 큰 값**을 쓴다. 한 덩어리 안이 `--s3`인데 덩어리 사이도 `--s3`이면 묶음이 보이지 않는다.
선과 박스로 나누기 전에 **간격으로 나눌 수 없는지 먼저** 본다.

## 4. 모서리 · 그림자 · 포커스 · 움직임

| 토큰 | 값 | 왜 |
|---|---|---|
| `--radius-sm` | 4px | 입력칸·버튼·칩. 6px만 돼도 13px 글자 높이에 비해 둥글어 장난스럽다. 4px는 모서리를 다듬기만 한다 |
| `--radius-lg` | 8px | 카드·패널·대화상자. 감싸는 면이 커지면 반지름도 커져야 **같은 둥근 정도**로 보인다 |
| `--radius-pill` | 999px | 숫자 뱃지 전용. 자릿수가 늘어도 모양이 안 흔들린다 |
| `--shadow-card` | 라이트 `0 1px 2px rgba(28,26,23,.06)` / 다크 `inset 0 1px 0 rgba(255,255,255,.04)` | 면을 한 겹 띄우는 정도. 진하면 촌스럽다. 어두운 바탕에서는 아래로 지는 그림자가 안 보여서 위쪽 옅은 빛으로 경계를 준다 |
| `--shadow-pop` | 라이트 `0 8px 24px rgba(28,26,23,.14)` | 진짜 떠 있는 것(드롭다운·대화상자)에만. 그림자는 두 단계가 끝이다 |
| `--focus-ring` | `0 0 0 1px var(--bg-1), 0 0 0 3px var(--accent)` | 안쪽 1px 띠가 요소와 링을 떼어 놓아 **어떤 바탕 위에서도** 링이 보인다. 연한 링(`0 0 0 3px var(--accent-weak)`)만 두면 흰 바탕 위 대비가 1.1이라 사실상 안 보인다 |
| `--dur-fast` / `--dur` | 120ms / 180ms | 색이 바뀜 / 모양이 바뀜. 사용자의 행동에 답하는 움직임만 쓴다. 화면이 뜰 때 올라오는 효과는 없다 |
| `--ease` | `cubic-bezier(.2,0,.3,1)` | 빨리 떠나고 천천히 멎는다 |

`prefers-reduced-motion`이 켜져 있으면 두 시간 값이 0이 된다.

## 5. 지키는 선 (한 줄씩)

- 이 문서와 `tokens.css` 밖에서 색·글자크기·간격·모서리·그림자 값을 직접 쓰면 **결함이다**
- 흐린 글자도 가장 어두운 바탕 위에서 4.5:1을 넘는다. 뜻을 가진 선은 3:1
- 키보드 포커스는 어떤 바탕 위에서도 보인다
- 한 화면에 주 행동은 하나. 강조색은 거기에만
- 다섯 상태(비어 있음 / 불러오는 중 / 저장됨 / 저장 안 됨 / 오류)가 모든 화면에 있다
- 버튼 이름은 무슨 일이 일어나는지 적는다. 같은 행동은 끝까지 같은 이름
- 요소를 더하기 전에 **지울 것부터** 찾는다
