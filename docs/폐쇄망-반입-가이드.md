# 폐쇄망 반입 가이드

인터넷이 없는 망에서 EA UseCase Studio를 쓰기 위한 절차입니다.
**인터넷 PC에서 준비 → 매체로 반입 → 폐쇄망 PC에서 설치** 순서입니다.

---

## 전제: 이 앱이 통신하는 곳

**없습니다.**

| 항목 | 상태 |
|---|---|
| 화면(렌더러)의 외부 통신 | CSP `connect-src 'self'` 로 원천 차단 |
| 외부 폰트 · CDN · 이미지 | 없음 (시스템 폰트만 사용) |
| 자동 업데이트 | 없음 |
| 텔레메트리 · 수집 | 없음 |
| 라이선스 확인 서버 | 없음 |
| 모델 호출 | **앱 프로세스 안에서 직접 추론** — 서버도 포트도 없음 |

모델은 `.gguf` 파일을 앱이 직접 읽어 메모리에 올립니다. HTTP 를 쓰지 않으므로
방화벽 예외도, 포트 개방도 필요 없습니다.

---

## 1단계 — 인터넷 PC에서 준비

### 1-1. 앱 설치본 만들기

```bash
git clone <repo> && cd ea-usecase-studio
npm install
npm run dist:win
```

`dist/` 에 생성된 **`EA UseCase Studio Setup x.y.z.exe`** 를 반입합니다.
Electron 런타임 · `node-llama-cpp` 네이티브 바이너리가 모두 포함되어 있어
폐쇄망 PC 에 Node.js 나 npm 을 설치할 필요가 없습니다.

> 폐쇄망 PC에서 소스를 빌드하려 하지 마세요. `npm install`이 레지스트리를 요구합니다.

### 1-2. 모델을 설치본에 넣기

빌드 **전에** `resources/model/` 에 `.gguf` 를 하나 넣으면 설치본에 함께 포장됩니다.

```
resources/model/qwen2.5-3b-instruct-q4_k_m.gguf   약 1.9 GB
```

Hugging Face 등에서 받아 넣으면 됩니다. Ollama 를 이미 쓰는 PC 라면
`%USERPROFILE%\.ollama\models\blobs\` 안의 큰 파일이 gguf 원본이므로 복사한 뒤
확장자를 `.gguf` 로 바꿔 넣어도 됩니다.

### 반입 목록 정리

| 파일 | 크기 |
|---|---|
| `EA UseCase Studio Setup x.y.z.exe` | 약 2 GB (앱 + 모델) |

**하나면 끝입니다.** 예전에는 Ollama 설치본과 `%USERPROFILE%\.ollama\models` 폴더를
manifest 경로까지 맞춰 복사해야 했는데, 그 단계가 통째로 없어졌습니다.

---

## 2단계 — 폐쇄망 PC에서 설치

1. `EA UseCase Studio Setup x.y.z.exe` 실행
2. 끝입니다.

모델이 설치본에 들어 있어 **설정할 것이 없습니다.** 확인하고 싶으면
설정 탭 → `사용 중인 모델` 에 파일명과 `앱에 포함됨` 이 보이고,
`연결 테스트` 를 누르면 실제로 올려 봅니다:

```
모델 OK — qwen2.5-3b-instruct-q4_k_m.gguf (1.8GB), VULKAN, 컨텍스트 8192
```

첫 `연결 테스트` 는 모델을 메모리에 올리느라 몇 초 걸립니다. 한 번 올린 모델은
설정을 바꿀 때까지 계속 들고 있으므로 이후 생성은 바로 시작됩니다.

> **GPU 가속**은 자동입니다. Vulkan/CUDA 를 찾으면 쓰고, 없으면 CPU 로 떨어집니다
> (느려질 뿐 동작은 합니다). `연결 테스트` 결과에 어느 쪽인지 표시됩니다.

---

## 3단계 — 어디로 나가는지 확인

설정 탭의 **네트워크** 카드가 전부 "없음" 으로 표시되는지 보면 됩니다.

검증 담당자에게는 이 두 가지를 보여주면 됩니다:

```bash
cat src/main/core/llm/index.ts   # 등록된 프로바이더 — 임베디드 하나
cat package.json                 # 런타임 의존성 — node-llama-cpp, exceljs
```

정책으로 막는 게 아니라 **코드에 통신 경로가 존재하지 않습니다.**

---

## 모델 없이 쓰기

모델 반입이 승인되지 않거나 아래 "네이티브 바이너리가 막힘" 에 걸려도 앱은 쓸모가
있습니다. 초안 생성만 못 할 뿐 편집 · 검증 · XMI 생성은 전부 로컬 계산입니다.

| 방법 | 설명 |
|---|---|
| JSON 직접 입력 | 다른 곳에서 만든 JSON 을 붙여넣어 프로젝트로 변환 |
| 빈 프로젝트로 시작 | 트리에서 직접 만들기 |
| 기존 `.eaucs` 열기 | 다른 PC 에서 만든 프로젝트를 이어서 편집 |

## 문제 해결

**연결 테스트에서 "응용 프로그램 제어 정책이 차단했습니다"**
→ 이 PC 의 **Smart App Control** 또는 WDAC 가 서명되지 않은 네이티브 모듈
(`llama-addon.node`) 로드를 막고 있습니다. 코드로는 우회할 수 없습니다.
설치본과 바이너리에 **코드 서명**을 하거나, 위 "모델 없이 쓰기" 로 쓰세요.

**설정 탭에 "앱에 포함된 모델을 찾지 못했습니다"**
→ 빌드할 때 `resources/model/` 에 `.gguf` 를 넣지 않았습니다. 넣고 다시
`npm run dist:win` 하세요. 급하면 `다른 모델 쓰기` 로 그 PC 의 `.gguf` 를
직접 지정해도 됩니다.

**생성이 느림**
→ `연결 테스트` 결과에 `CPU` 로 나오면 GPU 를 못 잡은 것입니다. 그래도 동작은
하지만 몇 배 느립니다. 컨텍스트 길이를 낮추면 VRAM 이 덜 들어 GPU 에 올라갈 수도
있습니다.

**유스케이스 이름이 뭉뚱그려짐**
→ 3B 모델의 한계입니다. 편집 탭에서 고치거나, 여유가 있으면 더 큰 gguf 로 바꾸세요
(설정 탭에서 파일만 바꾸면 됩니다).

**액터가 유스케이스마다 여러 명 붙음**
→ 정규화 단계에서 유스케이스당 최대 2개로 제한되므로 이 증상은 나오지 않아야 합니다.
그래도 보이면 원시 응답을 저장해 확인하세요.
