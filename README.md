# EA UseCase Studio

요구사항 정의서(엑셀/텍스트)를 넣으면 **유스케이스 초안**을 만들고, 트리에서 직접 다듬은 뒤
**Enterprise Architect에 임포트할 XMI**를 내보내는 Electron 데스크톱 앱입니다.

기존 n8n 워크플로(요구사항 텍스트 → LLM → JSON → XMI)를 데스크톱으로 옮기면서,
**"생성 후 수정할 수 없다"**는 가장 큰 한계를 없앴습니다.

```
요구사항 정의서 ──▶ [만들기] ──▶ LLM ──▶ 정규화 ──▶ [편집] ──▶ [검증] ──▶ [내보내기] ──▶ EA
   .xlsx / 텍스트                       (여기까지만 LLM)   트리+폼+캔버스        XMI 1.1
```

## 빠른 시작

```bash
npm install
npm run dev        # 개발 모드
npm run build      # 프로덕션 빌드 (out/)
npm run dist:win   # Windows 설치본 (dist/)
npm run smoke      # 핵심 파이프라인 스모크 테스트
npm run test       # 전체 테스트 (smoke + meta + local-llm + small + rel + vault)
npm run eval       # 생성 품질 점수판 (실제 EAP 정답과 비교. --cached 면 모델 없이 채점)
```

첫 실행 시 **설정 탭**에서 모델 파일(`.gguf`)을 지정하세요.
`.eaucs` 파일 경로를 실행 인자로 넘기면 그 프로젝트로 바로 열립니다
(파일 연결/드래그 앤 드롭용).

## 화면 구성

| 탭 | 하는 일 |
|---|---|
| **📄 만들기** | 엑셀 업로드 → 시트·컬럼 매핑 → LLM 입력 텍스트 조립 → 유스케이스 생성. 텍스트 붙여넣기·텍스트 파일 열기·HWP 파일 열기(한컴오피스 한글이 깔려 있어야 함)도 지원 |
| **🗂 편집** | 폴더 트리(대분류 → 중분류 → 유스케이스 / Actors)와 상세 폼. **여기가 본체** |
| **🔗 다이어그램** | 왼쪽 트리로 다이어그램 탐색 + UML 캔버스. 드래그한 좌표가 그대로 XMI에 반영됨 |
| **✔ 검증** | 중복 ID, 액터 없는 유스케이스, 끊어진 include/extend 등 임포트 전 점검 |
| **📤 내보내기** | EA XMI / 마크다운 볼트 / PlantUML / JSON |
| **⚙ 설정** | 사용 중인 모델 확인 · `모델 확인`(메모리에 올려 보기) · 외부 통신 없음 표 (읽기만 하는 화면) |

테마는 라이트가 기본이고 타이틀바의 🌙 / ☀ 로 전환합니다(선택 유지됨).

### 트리 조작
- `+` 버튼: 하위 항목 추가
- **드래그**: 유스케이스 → 다른 중분류로 이동, 중분류 → 다른 대분류로 이동
- `ID 다시 매기기`: 프로젝트 전체 ID를 규칙대로 다시 매긴다 (`GRP-001`, `UCD-GRP-001-01`). Ctrl+Z 로 되돌아간다
- 상단 검색: 이름·코드·요구사항ID·설명 전체 검색

### 다이어그램 탭
편집 탭과 같은 트리를 탐색 전용 모드로 왼쪽에 둡니다. 2depth 패키지 하나가
다이어그램 하나이므로, 트리에서 패키지나 유스케이스를 클릭하면 해당 다이어그램으로
바로 전환되고 현재 그려지는 패키지는 트리에서 파란 막대로 표시됩니다.

- **트리 배치**: 액터를 왼쪽 줄기로, 각 액터가 쓰는 유스케이스를 오른쪽 가지로 정렬
- **자동 배치**: 끌어 놓은 위치를 지우고 자동 배치로 되돌림
- 노드를 드래그해 옮긴 좌표가 그대로 XMI `DiagramElement geometry` 가 됩니다
- 유스케이스를 더블클릭하면 편집 탭의 상세 폼으로 이동합니다

액터 좌표는 **다이어그램(패키지)별로** 저장됩니다. 액터는 여러 다이어그램에 동시에
등장하므로 좌표를 전역으로 두면 한 곳에서 옮긴 위치가 다른 다이어그램을 망가뜨리고,
자동 배치도 "전체 액터 목록에서의 순번"을 쓰게 되어 5명 중 1번과 5번만 쓰는
다이어그램에서 두 액터가 800px 떨어져 그려집니다.

## 데이터 모델

```
Project
├── metadata      systemName / projectId(GUID 시드) / author
├── actors[]      Actor       → EA "Actors" 패키지
└── packages[]    UcPackage   → 요구사항 1건 = EA 패키지 1개 (UCD)
    ├── diagrams[]  Diagram   → 유스케이스 다이어그램 1..N
    └── useCases[]  UseCase   → EA UseCase 요소 (namespace = 패키지)
```

**요구사항 1건 = UCD 패키지 1개**가 모델의 축입니다. 대분류(GRP) 계층은 없습니다 —
표준 EA 산출물이 `Use Case Model` 바로 아래에 UCD를 평면으로 나열하기 때문입니다.
생성 파이프라인도 요구사항 1건마다 LLM을 호출하므로 단위가 정확히 일치합니다.

유스케이스는 **패키지에 속하고 다이어그램에 그려집니다**(EA와 같은 구조).
그래서 `useCases[]` 는 패키지가 들고, 각 UseCase 가 `diagramUid` 로 자기가 그려질
다이어그램을 가리킵니다. 한 요구사항을 여러 그림으로 나누고 싶으면 다이어그램을
추가하면 되고, 그때 UC 코드의 첫 번째 순번이 갈립니다.

`.eaucs` 파일(JSON)로 저장됩니다. **화면에 보이는 모든 값이 이 모델에 저장되고,
XMI는 오직 이 모델에서만 생성됩니다.** LLM 출력은 정규화 후 버려집니다.

### EA에 들어가는 모양

```
Use Case Model
├─ Actors
│   └─ 시스템관리자 · 정책담당자 …
├─ [UCD-SFR-001-PAD(플랫폼기반)-02] 분야별 연계서비스
│   ├─ [UC-SFR-001-PAD(플랫폼기반)-02-01-01] 연계 데이터 수집
│   └─ [UC-SFR-001-PAD(플랫폼기반)-02-01-02] 데이터 표준화 처리
└─ [UCD-SFR-001-PAD(플랫폼기반)-03] 알람서비스
    └─ [UC-SFR-001-PAD(플랫폼기반)-03-01-01] 관심 키워드 알람 수신
```

### ID 규칙
| 대상 | 형식 | 예 |
|---|---|---|
| UCD 패키지 | `UCD-{요구사항ID}` | `UCD-SFR-021-ADT1(맞춤형)` |
| 다이어그램 | `[{패키지코드}-{순번2}] {이름}` | `[UCD-SFR-021-ADT1(맞춤형)-01] 설문지 관리` |
| 유스케이스 | `UC-{요구사항ID}-{다이어그램2}-{UC2}` | `UC-SFR-021-ADT1(맞춤형)-01-04` |

**요구사항 ID는 원문 그대로 씁니다.** `SFR-021-ADT1(맞춤형)` 의 괄호도 한글도
깎지 않습니다. 표준 산출물이 원문을 유지하고, 정의서와의 추적성이 그 문자열로
걸리기 때문입니다. (정제는 업무구분 판정에만 씁니다 — 화면에 나가지 않습니다.)

색상: `PAD→yellow`, `SAD→purple`, `RPT→blue`, `INF→green`

## 모델

**모델은 앱에 들어 있습니다.** 설치하면 바로 쓰고, 사용자가 받거나 지정할 것이
없습니다. Ollama 설치도, 서버 실행도, API 키도 필요 없습니다.

```
설치 → 실행 → 문서 붙여넣기 → 생성
```

설정 탭은 **어떤 모델이 쓰이는지 보여주기만** 합니다:

```
사용 중인 모델
qwen2.5-3b-instruct-q4_k_m.gguf   [1.8GB] [앱에 포함됨]
설치본에 함께 들어 있어 따로 받거나 지정할 것이 없습니다.
```

더 큰 모델로 품질을 비교하고 싶을 때만 `다른 모델 쓰기` 를 펴서 `.gguf` 를
지정합니다. 비우면 다시 동봉된 모델로 돌아갑니다.

### 빌드할 때 모델 넣기

`npm run dist:win` **전에** `resources/model/` 에 `.gguf` 를 하나 넣으세요.
`electron-builder` 가 설치본에 함께 포장하고, 앱은 실행 시 그 폴더를 자동으로 찾습니다.

```
resources/model/qwen2.5-3b-instruct-q4_k_m.gguf   ← 여기
```

- 이 파일은 저장소에 커밋하지 않습니다(`.gitignore`).
- 개발 중(`npm run dev`)에도 같은 폴더를 읽습니다.
- 설치본 크기가 약 2GB 가 됩니다(앱 150MB + 모델 1.9GB).

| 항목 | 실측 (GTX 1660 6GB · qwen2.5 3B) |
|---|---|
| 모델 적재 | 8.1초 (앱 실행 중 한 번, 계속 들고 있음) |
| 요구사항 1건 생성 | 2~3초 |
| GPU | Vulkan 자동 인식. 안 되면 CPU 로 떨어짐 |

**밖으로 나가는 통신이 없습니다.** 모델이 앱 프로세스 안에서 돌기 때문에 호출할
서버가 없고, 서버를 띄우지 않으니 포트도 열지 않습니다. 기관 PC 에서 방화벽 팝업이
뜨지 않고, 반입할 것은 설치본과 `.gguf` 파일뿐입니다.

### 컨텍스트 길이를 충분히 주세요

입력이 컨텍스트를 넘으면 **에러가 나는 게 아니라 조용히 앞부분이 잘립니다.**
이 앱의 입력은 요구사항 본문 + 시스템 프롬프트라 2048로는 모자랍니다.
기본값 8192를 그대로 쓰시고, 문서가 길면 설정 탭에서 올리세요(VRAM을 더 씁니다).

### 생성 전략

모델이 **한 번에 만들어야 하는 JSON 크기**를 정합니다.

| 전략 | 호출당 출력 | 대상 |
|---|---|---|
| **자동** (기본) | 0.3~0.8 KB | **3B급** |
| 전체 한 번에 | 20 KB+ | 14B급 이상 |

**자동**이 핵심입니다. 계층·요구사항ID·패키지 트리·액터 목록은 앱이 결정론적으로
만들고, 모델에게는 요구사항 1건마다 "유스케이스 몇 개"만 시킵니다.

```
결정론(코드) : 요구사항ID, 패키지 트리, 액터 목록, 코드 채번, GUID, 좌표
모델         : 유스케이스 이름 / 흐름 / 액터 연결
```

그래서 프롬프트가 짧아 3B급 컨텍스트에 여유롭게 들어가고, 한 요구사항이 실패해도
나머지는 그대로 살아남습니다. 실패한 건은 요구사항명으로 채워져 트리에 자리는
잡히므로 편집 탭에서 이름만 고치면 됩니다.

### 3B 모델의 한계

유스케이스 이름이 "데이터 수집", "권한 설정"처럼 뭉뚱그려지고 흐름 문장도 거칩니다.
**초안을 뽑고 편집 탭에서 다듬는** 용도입니다. 앱은 모델이 실수할 것을 전제로
만들어져 있습니다:

- 같은 유스케이스를 반복 생성 → 이름이 같으면 하나만 남기고, 요구사항당 12건으로 자름
- 액터 목록을 통째로 복사 → 유스케이스당 2개로 제한, 전부 복사한 경우는 주 액터 1개만
- 없는 액터를 지어냄 → 원문에 그 표현이 실제로 있어야 인정
- 코드펜스·잡담·잘린 JSON·배열만 반환 → 복구 후 1회 재시도

```bash
npm run test:small     # 3B 모델의 7가지 실수를 재현해 내성 검증
npm run test:embedded -- <모델.gguf>   # 진짜 모델을 올려 파이프라인을 끝까지 검증
```

### 왜 프로바이더를 하나만 남겼나

한동안 Ollama · OpenAI 호환 · Anthropic · Google 넷을 함께 뒀습니다. 고를 수 있다는 건
좋아 보였지만 실제로는 설정 탭에 엔드포인트 · API 키 · 모델명 · 폐쇄망 경고가
프로바이더마다 따로 붙었고, 문서도 "어느 프로바이더를 쓰느냐에 따라" 로 갈라졌습니다.
정작 납품 대상에서 쓰는 건 하나입니다.

지우면서 함께 사라진 것들:

| | 전 | 후 |
|---|---|---|
| 프로바이더 어댑터 | 4개 | 1개 |
| 런타임 의존성 | `@anthropic-ai/sdk` · `@google/generative-ai` · `exceljs` | `node-llama-cpp` · `exceljs` |
| API 키 저장 | `safeStorage` + `secrets.bin` + IPC 2개 + 입력 UI | **없음** (인증할 상대가 없다) |
| 설정 탭 | 프로바이더 버튼 줄 · 엔드포인트 · 키 · 폐쇄망 경고 | 모델 파일 · 컨텍스트 · 전략 · 프롬프트 |

고를 것이 없으면 틀릴 것도 없습니다. 다시 필요해지면 파일 하나 + `llm/index.ts`
한 줄입니다 — 그 구조는 그대로 남겨 뒀습니다.

> ⚠ **코드 서명 정책의 영향을 받습니다.**
> 네이티브 바이너리(`llama-addon.node`)라서, Windows 의 **Smart App Control** 이나
> WDAC 가 켜져 있으면 로드가 차단됩니다 —
> *"An Application Control policy has blocked this file"*.
> 그 경우 `연결 테스트` 가 그 사실을 그대로 알려 주고, **편집 · 검증 · XMI 생성은
> 모델 없이도 그대로 동작합니다.** 배포 대상 PC 에 이 정책이 있다면 설치본과
> 바이너리에 **코드 서명**이 필요합니다.

## 유스케이스 사이의 관계 (include / extend)

생성이 끝난 뒤 **관계를 한 번 더 묻습니다.**

요구사항 단위 생성은 요구사항 1건씩 따로 호출합니다. 그래야 3B급 모델이 완주하지만,
그 호출은 **다른 유스케이스의 존재를 모릅니다.** include/extend 는 정의상 유스케이스
둘 사이의 관계라 거기서는 나올 수가 없습니다. 그래서 프로젝트가 다 만들어진 뒤
유스케이스 목록 전체를 놓고 한 번 더 묻습니다. (액터를 같은 이유로 마지막에 한 번 더
묻습니다 — `extract.ts` 의 액터 정리와 같은 패턴입니다.)

**모델은 번호만 말합니다.** 유스케이스 코드는 `UC-SFR-001-PAD(플랫폼기반)-02-01` 처럼
길고 괄호와 한글이 섞여 있어 소형 모델이 그대로 못 옮깁니다. 번호로 주고받으면 틀릴
여지가 없고, 검증도 "범위 안의 정수인가"로 끝납니다.

판정은 전부 코드가 합니다 (`relations.ts`):

| 검사 | 버리는 것 |
|---|---|
| 범위 | 목록에 없는 번호 |
| 자기참조 | `from == to` |
| 중복 | 같은 쌍 두 번 |
| 순환 | 관계를 따라가 되돌아오는 것 (EA에서 무한 루프로 읽힘) |
| 총량 | 유스케이스 3건당 1건 상한 · 하나당 최대 2건 |

총량 상한이 중요합니다. 액터 때와 똑같이, 그냥 두면 소형 모델은 **모든 쌍을 이어
붙입니다.** 유스케이스 6건에 30건의 관계를 제안한 응답을 상한이 2건으로 잘라냅니다.

유스케이스가 80건을 넘으면 제안을 **건너뜁니다.** 목록이 길어지면 모델이 번호를 세다
놓치고, 검증을 통과하는 엉뚱한 쌍이 늘어납니다. "그럴듯한 오답"이 "없음"보다 나쁩니다.

호출이 실패해도 예외를 던지지 않습니다 — 관계는 없어도 모델이 성립하고, 여기서 던지면
다 만들어 놓은 유스케이스가 통째로 날아갑니다. 사실만 경고에 남기고 넘어갑니다.

### 다이어그램에서 직접 잇기

툴바의 **🔗 연결** 을 켜고 노드에서 노드로 끌어 놓으면 됩니다. Esc 로 끕니다.

| 무엇에서 무엇으로 | 만들어지는 것 |
|---|---|
| 액터 ↔ 유스케이스 | 연결선 (association) — 방향 무관 |
| 유스케이스 → 유스케이스 | 툴바에서 고른 `«include»` 또는 `«extend»` |

- 끌고 있는 동안 **고무줄 선**이 따라오고, 놓을 수 있는 노드에 올리면 테두리가 강조됩니다
- **이미 있는 연결을 다시 이으면 끊깁니다** (인스펙터 칩과 같은 동작)

### 액터를 여러 유스케이스에 한 번에 붙이기

액터를 고르면 인스펙터에 **`이 다이어그램 N건에 연결`** / **`연결 해제`** 가 나옵니다.

액터가 틀리게 붙거나 아예 안 붙는 건 소형 모델에서 늘 생깁니다 — 운영자가 하는
등록·설정·발송을 이용자에게 붙이는 식입니다. 하나씩 고치면 다이어그램당 열 번을
클릭해야 하는데, 실제로는 "이 UCD는 전부 운영자가 하는 일"인 경우가 많아
통째로 처리할 수 있게 뒀습니다.

### 연결선 끊기

**선을 클릭**하면 빨갛게 표시되고 가운데에 `✕` 가 뜹니다. `✕` 를 누르거나 `Delete`
키로 끊습니다. 빈 바닥을 클릭하면 선택이 풀립니다. 액터 연결선과 include/extend
둘 다 같습니다.

보이는 선은 1.2px 이라 그대로는 누를 수 없어서, 투명하고 굵은 선을 밑에 깔아
클릭 판정으로 씁니다. 액터 막대인간에 투명 사각형을 깐 것과 같은 방식입니다.

되돌리기가 없으므로 무엇을 끊었는지 항상 토스트로 알립니다.
- 고리가 생기는 연결은 거부하고 왜 거부했는지 알려줍니다 — AI 제안과 같은 규칙입니다
  (`shared/graph.ts` 를 양쪽이 함께 씁니다)

연결 모드를 켜면 드래그가 "옮기기"에서 "잇기"로 바뀝니다. 같은 제스처에 두 뜻을
얹으면 옮기려다 선을 긋게 되므로 모드로 나눴습니다.

액터 팔레트에서 **액터를 유스케이스 위로 끌어다 놓아도** 배치와 연결이 함께 됩니다.

### 인스펙터에서 편집하기

유스케이스를 고르고 `관계 · 식별` 을 펼치면 include/extend 를 칩으로 고릅니다.
대상은 **프로젝트 전체**입니다 — include 로 묶이는 건 대개 공통 기능(로그인, 권한확인)
이고 그건 다른 UCD에 있기 때문입니다. 같은 UCD 것이 먼저 보이고, 다른 UCD는 `↗` 로
표시됩니다. 검색으로 좁힐 수 있습니다.

```bash
npm run test:rel     # 모델이 어떤 헛소리를 해도 프로젝트가 안 망가지는지 검증
```

## 폐쇄망(오프라인) 사용

인터넷 없는 망에서 그대로 쓸 수 있습니다. 반입 절차는
**[docs/폐쇄망-반입-가이드.md](docs/폐쇄망-반입-가이드.md)** 를 보세요.

**런타임에 외부로 나가는 지점이 없습니다.**

| 항목 | 상태 |
|---|---|
| 렌더러의 외부 통신 | CSP `connect-src 'self'` 로 원천 차단 |
| 외부 폰트 · CDN | 없음 (시스템 폰트만) |
| 자동 업데이트 · 텔레메트리 | 없음 |
| 모델 호출 | 앱 프로세스 안에서 직접 추론 — **네트워크 없음** |

### 모드가 아니라 구조입니다

예전에는 "폐쇄망 모드" 토글이 있었습니다. 클라우드 프로바이더를 잠그고, 엔드포인트가
사설 대역인지 검사하고, 설정 탭에 허용/차단 표를 그리고, 그 정책만 검증하는 테스트가
39개 있었습니다. 그 뒤에는 클라우드 어댑터를 넣어 두고 "어디로 나가는지" 를 화면에
표시하는 방식으로 바꿨습니다.

지금은 **막을 것 자체가 없습니다.** 프로바이더가 임베디드 하나뿐이고 그건 HTTP 를
쓰지 않습니다. 정책으로 지키는 게 아니라 코드에 통신 경로가 존재하지 않는 것이라,
검증 담당자에게는 이 두 가지를 보여주면 됩니다:

```bash
cat src/main/core/llm/index.ts   # 등록된 프로바이더 — 임베디드 하나
cat package.json                 # 런타임 의존성 — node-llama-cpp, exceljs
```

### 모델 없이도

모델 파일을 못 넣거나 네이티브 바이너리가 정책에 막혀도 **저장한 프로젝트(`.eaucs`) 열기**
로 편집 · 검증 · XMI 생성이 전부 가능합니다. 모델은 초안을 뽑는 데만 씁니다.

## EA 임포트

1. 내보내기 탭 → **XMI 파일로 저장**
2. EA: `Project → Model Import/Export → Import Package from XMI`
3. 대상 패키지 선택, **Strip GUIDs 체크 해제**

GUID는 `프로젝트 ID + 엔티티 uid`의 SHA-1로 **결정적으로** 생성됩니다.
같은 프로젝트를 수정해 다시 내보내면 동일 GUID가 나오므로 EA가 **갱신**으로 처리합니다
(요소가 중복 생성되지 않음). 단, **프로젝트 ID를 바꾸면 전부 새 요소가 됩니다.**

## 마크다운 볼트 (검토·인수인계용)

내보내기 탭 → **볼트 폴더 만들기** 를 누르면 유스케이스·액터·다이어그램을
노트 한 장씩으로 푸는 폴더를 만듭니다. 고른 폴더 **아래에** 시스템명 폴더가
하나 생기고 그 안에만 씁니다.

```
예시 시스템/
├─ 예시 시스템.md    인덱스 (대분류·액터 목록)
├─ 액터/정책담당자.md                     이 액터가 등장하는 유스케이스 목록
└─ GRP-001 통합서비스/
   ├─ GRP-001 통합서비스.md               대분류 인덱스
   ├─ UCD-GRP-001-01 분야별 연계서비스.md   다이어그램 (PlantUML 코드펜스 포함)
   └─ UC-SFR-001-PAD-02-01.md           유스케이스 한 건
```

노트끼리 위키링크로 엮여 있어 **EA 없이도** 요구사항 ID → 유스케이스,
액터 → 관련 유스케이스로 따라갈 수 있습니다. 옵시디언에서 열면 백링크와
그래프 뷰가 그대로 붙고, **없어도 그냥 마크다운 문서로 읽힙니다** — 폐쇄망에서
옵시디언 반입이 승인되지 않아도 산출물이 죽지 않게 하려는 의도입니다.
EA 라이선스가 없는 현업·PM·감리에게 검토를 돌릴 때 쓰세요.

### 되읽지 않는다 (단방향)

이쪽은 **읽기 전용 사본**입니다. 볼트를 고쳐도 원본 `.eaucs` 에 반영되지 않으며,
되가져오는 임포터도 없습니다. 의도적입니다:

> EA GUID는 `SHA-1(projectId::uid)` 로 채번되고(`eaid.ts`), 그 `uid` 는 `.eaucs` 에
> 영구 저장된 값입니다. 마크다운을 원본 삼아 편집하고 되읽으면, 노트를
> 지웠다 다시 쓰거나 복제하는 순간 uid 가 흔들리고 → EA에서 "갱신"이
> **"중복 생성"** 으로 바뀝니다. frontmatter 의 `uid` 는 대조용으로만 적어 둡니다.

모델을 고치려면 앱에서 편집한 뒤 다시 내보내세요. 같은 위치에 다시 내보내면
노트가 덮어쓰입니다 (삭제된 요소의 오래된 노트는 남으니, 필요하면 폴더를 비우고 다시 만드세요).

```bash
npm run test:vault   # 링크 무결성·파일명·frontmatter 검증
```

### 화면 규칙 (styles.css)

디자인을 감각이 아니라 **규칙**으로 둡니다. 값을 새로 만들지 말고 아래 스케일에서 고르세요.

```
간격   --s1 4  --s2 8  --s3 12  --s4 16  --s5 24  --s6 40
글자   --fz-xs 11  --fz-sm 12  --fz-md 13(본문)  --fz-lg 15
모서리 --radius-sm 6  --radius-lg 8
```

| 원칙 | 이 앱에서의 규칙 |
|---|---|
| **근접성** | 같은 묶음 안은 `--s1~s2`, 묶음 사이는 **반드시 한 단계 큰 값**. 한 덩어리 안이 `--s3`인데 덩어리 사이도 `--s3`이면 묶음이 보이지 않습니다 |
| **공동 영역** | 역할이 다른 버튼 무리는 `.tool-group` 으로 감쌉니다 (다이어그램 툴바: 탐색 · 연결 · 배치 · 내보내기) |
| **유사성** | "켜져 있음"의 표현은 하나뿐입니다 — `.mode-on` · `.chip.on` · `.tiny.on` 이 같은 규칙을 씁니다. 보조 설명은 전부 `.hint` |
| **초점** | **화면당 파란 버튼 하나.** 같은 화면의 다른 동작은 기본 버튼입니다 |
| **폐쇄성** | 카드는 테두리 + 아주 옅은 그림자로 "닫힌 그릇"이 됩니다. 제목 아래 실선이 카드마다 같은 자리를 지나 세로로 격자를 만듭니다 |
| **연결성** | 트리는 한 단계 = `--s5` 고정 보폭으로 들여쓰고, 세로 안내선으로 부모-자식을 잇습니다 |
| **평행 · 대칭** | 값은 스케일에서만. 새 수치를 쓰면 그 순간 위 규칙들이 전부 무너집니다 |

### 색 — 눈대중이 아니라 계산으로

모든 글자색과 배경색 조합이 **WCAG AA(4.5:1)** 를 넘습니다. 라이트·다크 양쪽 다입니다.

```
--fg       on --bg-1   라이트 15.55   다크 14.32
--fg-dim   on --bg-1   라이트  6.39   다크  6.93
--fg-mute  on --bg-3   라이트  4.53   다크  4.84   ← 가장 빡빡한 조합
```

`--fg-mute` 는 원래 라이트에서 흰 배경 대비 **3.23** 이었습니다. `.muted` · `.hint` ·
`.pane .sub` 처럼 **11px 보조 텍스트가 전부 이 색**이라, 흐린 게 아니라 잘 안 보였습니다.

**네이티브 컨트롤에는 색을 직접 지정해야 합니다.** `<select>` 의 펼침 목록, 선택
하이라이트, 자리표시자, 체크박스는 페이지가 색을 안 주면 Chromium 이 **운영체제
테마**로 그립니다. Windows 가 다크 모드면 라이트 테마의 흰 배경 위에 흰 글씨가
나옵니다. `option` · `::placeholder` · `::selection` · `accent-color` 를 전부
토큰으로 못 박아 뒀습니다 — 지우지 마세요.

정리 전에는 간격이 8종(2·4·5·6·8·10·12·14), 글자가 10종(9~16·11.5)이었습니다.
값이 촘촘히 흩어져 있으면 눈이 간격의 **비율**로 묶음을 읽지 못합니다.

### 다이어그램을 SVG로 직접 그린 이유
캔버스에서 옮긴 좌표가 **그대로 XMI `DiagramElement geometry`로 나가야** 하는데,
범용 그래프 라이브러리(React Flow 등)는 자체 좌표계와 자동 레이아웃을 강제해 그 1:1
대응이 깨집니다. UML 표기(막대인간 + 타원)도 어차피 커스텀 노드를 그려야 합니다.
문서용 렌더링이 필요하면 PlantUML 텍스트를 내보냅니다.

## 알려진 제약

- **XMI는 EA XMI 1.1(UML 1.3) 한 방향만** 지원합니다. EA에서 되읽어오는 임포터는 없습니다.
- **요구사항끼리의 관계(선행/후행/참조)는 모델에 없습니다.** 관계는 유스케이스
  사이의 include/extend 만 표현됩니다.
- include/extend는 `UML:Dependency` + 스테레오타입으로 내보냅니다. EA 버전에 따라
  연결선 표기가 다를 수 있으니 첫 임포트 때 한 번 확인하세요.
- 엑셀 [요구사항 상세] 블록은 LLM 입력 텍스트로만 합쳐집니다. 요구사항ID 기준으로
